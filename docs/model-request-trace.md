# Trace의 모델 요청 근거

AT-12·AT-18의 실행 흐름을 모델 요청 단계까지 확장한다. 실제 원본 Run에는
`model.request`가 있어도 기존 Trace는 호출·도구·승인만 node로 투영해 모델 단계가
보이지 않았다. 모델 요청 시작·종료 관측을 node와 소속 edge로 표시하고
Run/호출 그룹 내부와 그룹 상세의 별도 단위 집계에 포함한다.

기존 `/api/runs/:key/tools`가 현재 인가를 전후 확인하며 읽는 제한된 SSE 한 번을
재사용한다. 새 화면의 `?include=model-requests` 요청에만 선택적 응답 필드를
추가한다. 기존 URL은 구 응답 모양을 유지해 이미 열려 있는 구버전 화면도
도구 근거를 계속 읽는다. 저장된 정규 이벤트·digest·DB schema는 변경하지 않는다.
새 화면도 구 API 응답에 모델 근거 필드가 없으면 0건으로 해석하지 않는다.
허용된 metadata는 요청 provider profile·모델, 시작/종료 시각·sequence와 SDK가
보고한 소요 시간이다. 원본 SDK Session ID는 Run 범위의 불투명 hash로만 문맥을
구분하고 화면·이벤트 저장소에 원문으로 전달하지 않는다. 요청/응답 본문·인수·
credential과 요청별 토큰·비용은 제공하지 않는다. Run 합계를 요청에 배분하지 않는다.

원본에 provider request ID가 없으므로 화면 항목의 식별자는 Run과 시작 근거
sequence다. 같은 원본 문맥에 한 시작과 한 종료가 있고 사이의 journal이 온전할
때만 대응한다. 중첩 시작·누락 sequence·식별 불가 또는 상충하는 중간 모델
이벤트가 있으면 대응을 미확정으로 남긴다. 종료만 관측한 항목은 추가 요청
시작으로 세지 않는다. SDK 종료 이벤트는 모델 성공·Run 성공·업무 수용과 별도다.

명시된 invocation ID와 같은 Run에서 실제 관측된 호출이 있을 때만 그 호출
그룹에 넣는다. 참조만 있거나 생명주기를 확인하지 못하면 Run 안에 남긴다.
같은 문맥의 겹치지 않는 관측 구간 사이에는 `기록 순서` edge를 표시하며,
의존 관계로 바꾸지 않는다. 범위·표시 한도·접기 이후에도 원본 sequence를 유지한다.
사용자·출처·Run·현재 인증 문맥이 바뀌거나 source가 stale이면 이전 근거를 숨긴다.

2026-11-13 실제 원본 읽기에서 운영 Run
`82f7e1fd-8fe2-4da1-8307-99f3e016f48c`의17개 이벤트와 요청 시작seq4·
`codex-native`/`gpt-6.1-sol`을 대조했다. 대응 종료가 없어 성공 Run 안에서도
`Run 종료·요청 종료 미확인`으로 남긴다. 분리된 로컬 화면에서 node 선택과
provider/model·시각·seq 상세, Run→모델 edge 의미를 확인했다. 새 모델 요청은 없다.
별도로 실제 Linux peer Run의 보존 SQL archive SHA를 확인한 뒤49개 행에서
모델 시작/종료seq6/45·SDK 보고4233ms를 대조했다. 이는 archive readback이며
새 live source 실행이나 운영 SDK/worker 전환 증거가 아니다.

독립 리뷰의 중간 이벤트 오류 누락과 참조 호출 소속 문제를 보완했다. 관련
회귀 검사·기존 도구/인가/그룹 검사를 수행한다. 현재 구현의 원격 CI·동결 배포와
운영 Entra GUI는 각각 실제 결과가 확보될 때 기록한다. 전체 goal은14/21
(동일 가중치66.7%)이며 운영 executor·교차 앱 업무 수용·SSO 검증이 남는다.
